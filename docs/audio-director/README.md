# AI Audio-Director — план реализации

Полуавтоматическое создание многоголосых аудиокниг из FB2: расширение приложения `book-map`.

## Как пользоваться этой папкой

Каждый файл — самостоятельная единица работы для отдельной сессии / отдельного агента. Файлы с префиксом `0X-prX-...md` описывают итерации (Pull Requests). У каждой итерации есть:
- Цель и пользовательский сценарий
- Список изменяемых/создаваемых файлов
- Acceptance criteria (что должно работать после мержа)
- Артефакты для следующей итерации (что предыдущий PR оставляет следующему)
- Open questions / риски

`voices.md` и `prompts.md` — справочные документы, которые шарятся между всеми итерациями.

## Стек и контекст

- React 19 + Vite + TS, Tailwind 4, Zustand, React Flow, fast-xml-parser
- Хранилище: IndexedDB (локально) + Supabase (опционально)
- Все вызовы к Gemini делаются прямо из браузера (как уже работает OpenRouter в `aiService.ts`). Ключ — в `localStorage`.
- Используем 3 модели:
  - `gemini-3.1-pro-preview` — глобальный анализ книги
  - `gemini-3.1-flash-lite-preview` — поглавная разметка
  - `gemini-3.1-flash-tts-preview` — TTS

## Принципы

1. **Не ломать существующий book-map.** Все новые файлы — в новых директориях (`components/AudioDirector/`, `lib/gemini*.ts`, `store/audioStore.ts`, `types/audio.ts`). Существующие файлы трогаем только для роутинга (`App.tsx`), Settings (`SettingsModal.tsx`), и ссылок входа в фичу (например, новая кнопка в `BookList`).
2. **Стейт фичи изолирован.** Касты, разметка глав, аудио-чанки — отдельные IndexedDB stores.
3. **Параметризованные модели.** Имена моделей берутся из настроек, чтобы агент мог менять модель без правки кода (на случай, если billing / preview status сменится).
4. **Кеш на уровне блоков.** Ключ кеша = sha256(text + voiceId + stylePrompt + modelVersion). При правке одного блока перегенерируется только он.
5. **Нет ffmpeg.** PCM-чанки склеиваются в WAV через массив байт + один WAV-хедер. Всё клиентское.
